لا تحذف الملفات مباشرة الآن.

نفّذ هذه المهمة على مراحل آمنة فقط لحل مشكلة التخزين والملفات اليتيمة Orphaned Files.

الهدف:
تنظيف ملفات التخزين غير المرتبطة بأي سجل في قاعدة البيانات، مع منع تكرار المشكلة مستقبلًا.

━━━━━━━━━━━━━━
المرحلة 1: فحص آمن بدون حذف
━━━━━━━━━━━━━━

أنشئ أداة Admin Cleanup Tool تعمل بوضع Preview / Dry Run أولاً.

يجب أن تقوم الأداة بفحص جميع ملفات Storage ومقارنتها مع قاعدة البيانات.

اعتبر الملف يتيماً فقط إذا لم يكن مرتبطًا بأي من الجداول التالية أو أي جدول يستخدم صورًا/ملفات:

- technicians
- companies
- suppliers
- service_requests
- public_requests
- offers
- advertisements / ads
- profiles
- applications
- galleries
- any other table that stores image_url, file_url, avatar_url, photo_url, logo_url, gallery_urls, attachments, images

مهم جدًا:
- افحص كل الأعمدة التي تحتوي على روابط أو مسارات ملفات.
- لا تعتمد على جدول واحد فقط.
- لا تحذف أي شيء في هذه المرحلة.

اعرض تقريرًا يحتوي على:
- عدد الملفات الإجمالي.
- عدد الملفات المرتبطة.
- عدد الملفات اليتيمة.
- الحجم الإجمالي للملفات اليتيمة.
- قائمة أول 50 ملفًا يتيماً كمثال.
- سبب اعتبار كل ملف يتيماً.

━━━━━━━━━━━━━━
المرحلة 2: إنشاء نسخة أمان
━━━━━━━━━━━━━━

قبل أي حذف:

- صدّر قائمة كاملة بجميع الملفات التي سيتم حذفها إلى ملف JSON أو CSV.
- احفظ الملف باسم واضح مثل:
orphaned-files-backup-list-[date].json

يجب أن يحتوي على:
- file path
- bucket name
- file size
- created_at إن وجد
- سبب الحذف

لا تبدأ الحذف إلا بعد إنشاء هذا التقرير.

━━━━━━━━━━━━━━
المرحلة 3: حذف آمن فقط بعد التأكيد
━━━━━━━━━━━━━━

بعد عرض التقرير، انتظر موافقتي الصريحة قبل الحذف.

إذا وافقت، احذف فقط الملفات التي ظهرت في تقرير Dry Run.

نفّذ الحذف على دفعات صغيرة batch deletion وليس دفعة واحدة.

بعد كل دفعة:
- سجّل عدد الملفات المحذوفة.
- سجّل أي أخطاء.
- لا تحذف الملفات التي فشل التحقق منها.

بعد الانتهاء اعرض:
- عدد الملفات المحذوفة.
- الحجم الذي تم تحريره.
- عدد الملفات المتبقية.
- أي ملفات فشل حذفها.

━━━━━━━━━━━━━━
المرحلة 4: منع تكرار المشكلة
━━━━━━━━━━━━━━

بعد التنظيف، أصلح سبب المشكلة:

1. لا ترفع الصور إلى Storage بمجرد اختيار المستخدم للصورة إذا كان هذا هو سبب المشكلة.
   الأفضل:
   - ارفع الصورة فقط عند الضغط على حفظ / إرسال.
   أو:
   - إذا تم الرفع قبل الحفظ، خزّنها كملف مؤقت temporary مع TTL.

2. إذا رفع المستخدم صورة ثم لم يكتمل حفظ النموذج:
   - احذف الصورة تلقائيًا.
   - أو ضعها في temporary uploads ويتم تنظيفها لاحقًا.

3. عند حذف فني أو شركة أو مورد أو إعلان أو طلب:
   - احذف الملفات المرتبطة به من Storage تلقائيًا.

4. عند استبدال صورة قديمة بصورة جديدة:
   - احذف الصورة القديمة إذا لم تعد مستخدمة.

5. أضف وظيفة تنظيف دورية:
   - تبحث عن الملفات المؤقتة أو اليتيمة الأقدم من 24 أو 48 ساعة.
   - تعرض Preview قبل الحذف في البداية.

قيود مهمة
━━━━━━━━━━━━━━

- لا تحذف أي ملف مرتبط بمستخدم أو بروفايل أو طلب أو إعلان.
- لا تحذف أي شيء قبل عرض تقرير Dry Run.
- لا تحذف أي شيء قبل موافقتي الصريحة.
- لا تغيّر التصميم العام.
- لا تغيّر نظام الطلبات.
- لا تغيّر نظام التسجيل.
- لا تستخدم higher power mode.
- توقف بعد عرض تقرير Dry Run وقائمة الملفات المقترحة للحذف.

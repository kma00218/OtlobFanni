نفّذ المطلوب التالي بدقة على تطبيق "اطلب فني".

مهم جدًا:
لا تعيد بناء التطبيق من الصفر.
لا تغيّر فكرة التطبيق.
لا تضف أفكار جديدة من عندك.
لا تغيّر التصميم العام إلا إذا كان ضروريًا للوحة التحكم.
لا تستخدم Firebase.
لا تستخدم MongoDB.
لا تستخدم Backend منفصل.
استخدم Supabase فقط.
نفّذ المطلوب خطوة بخطوة كما هو مكتوب.

الهدف:
أريد لوحة تحكم احترافية ومتكاملة قدر الإمكان لتطبيق "اطلب فني"، مع Super Admin يتحكم في كل شيء، و Sub Admins بصلاحيات محدودة.

التقنيات المطلوبة:
- React
- Vite
- Tailwind CSS
- React Router DOM
- Supabase
- Supabase Auth
- Supabase Database
- Supabase Edge Functions
- Lucide React للأيقونات

مهم أمنيًا:
- ممنوع وضع SUPABASE_SERVICE_ROLE_KEY داخل React.
- ممنوع وضع service_role key في أي ملف Frontend.
- استخدم VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY فقط داخل React.
- استخدم SUPABASE_SERVICE_ROLE_KEY فقط داخل Supabase Edge Functions.
- فعّل Row Level Security على الجداول.

--------------------------------------------------
أولًا: الدخول المخفي للوحة التحكم
--------------------------------------------------

لا أريد زر Admin ظاهر للمستخدمين.

في الصفحة الرئيسية:
- عند الضغط على شعار "اطلب فني" خمس مرات خلال 5 ثواني
- افتح صفحة:
  /admin/login

لا تظهر أي علامة أو زر للمستخدم العادي يدل على وجود لوحة تحكم.

--------------------------------------------------
ثانيًا: تسجيل دخول لوحة التحكم
--------------------------------------------------

أنشئ صفحة:
 /admin/login

تستخدم Supabase Auth بالبريد وكلمة المرور.

بعد تسجيل الدخول:
- اقرأ بيانات المستخدم من جدول profiles.
- إذا role = super_admin و is_active = true افتح /admin/dashboard
- إذا role = sub_admin و is_active = true افتح /admin/dashboard
- غير ذلك امنع الدخول وأظهر رسالة:
  "غير مصرح لك بالدخول إلى لوحة التحكم"

احمِ جميع روابط /admin.
أي شخص غير مسجل دخول يتم تحويله إلى /admin/login.

--------------------------------------------------
ثالثًا: الصلاحيات
--------------------------------------------------

1. Super Admin

الـ Super Admin يستطيع تغيير أي شيء في التطبيق:

- إدارة الفنيين
- إدارة التخصصات
- إدارة المدن
- إدارة الطلبات
- إدارة الإعلانات
- إدارة المستخدمين
- إنشاء عدد غير محدود من Sub Admins
- تفعيل وتعطيل Sub Admins
- تغيير مدينة Sub Admin
- تغيير صلاحيات Sub Admin
- إدارة إعدادات التطبيق
- إدارة محتوى الصفحة الرئيسية
- إدارة أرقام التواصل
- إدارة WhatsApp الدعم
- مشاهدة كل الإحصائيات
- رؤية كل المدن
- رؤية كل الفنيين
- رؤية كل الطلبات
- حذف وتعديل وإضافة أي شيء

2. Sub Admin

صلاحية محدودة:

- يرى Dashboard مختصر
- يرى فقط بيانات المدينة المرتبط بها
- يستطيع إضافة فنيين في مدينته فقط
- يستطيع تعديل الفنيين في مدينته فقط
- يستطيع تفعيل أو تعطيل فنيين في مدينته فقط
- يستطيع مراجعة الطلبات الخاصة بمدينته فقط
- يستطيع تغيير حالة الطلب داخل مدينته فقط
- لا يستطيع إدارة المدن
- لا يستطيع إدارة التخصصات العامة
- لا يستطيع إدارة الإعدادات العامة
- لا يستطيع إنشاء Admin أو Sub Admin
- لا يستطيع رؤية بيانات المدن الأخرى
- لا يستطيع حذف Super Admin
- لا يستطيع تغيير صلاحياته

--------------------------------------------------
خامسًا: Row Level Security
--------------------------------------------------

فعّل RLS على كل الجداول.

اكتب سياسات واضحة:

Public users:
- يستطيعون قراءة cities النشطة فقط
- يستطيعون قراءة categories النشطة فقط
- يستطيعون قراءة technicians النشطين والمعتمدين فقط
- يستطيعون إنشاء service_request جديد فقط
- لا يستطيعون تعديل أو حذف أي شيء

Super Admin:
- يستطيع قراءة وإضافة وتعديل وحذف كل شيء

Sub Admin:
- يستطيع قراءة technicians في مدينته فقط
- يستطيع إضافة technician في مدينته فقط
- يستطيع تعديل technician في مدينته فقط
- يستطيع قراءة service_requests في مدينته فقط
- يستطيع تعديل حالة service_requests في مدينته فقط
- لا يستطيع تعديل cities
- لا يستطيع تعديل categories
- لا يستطيع تعديل settings
- لا يستطيع تعديل users إلا بياناته المحدودة إن لزم

--------------------------------------------------
سادسًا: Supabase Edge Functions
--------------------------------------------------

أنشئ Edge Function باسم:

create-sub-admin

المسار:
supabase/functions/create-sub-admin/index.ts

وظيفتها:
- يستقبل الطلب من Super Admin فقط
- يتحقق من المستخدم الحالي
- يتحقق من profile الخاص به
- يسمح فقط إذا role = super_admin و is_active = true
- ينشئ مستخدم جديد في Supabase Auth
- يضع له email و temporary password
- ينشئ profile له role = sub_admin
- يربطه بمدينة city_id
- يرجع رسالة نجاح

مهم:
- استخدم SUPABASE_SERVICE_ROLE_KEY داخل Edge Function فقط
- لا تضع service_role key في React

أنشئ Edge Function ثانية باسم:

update-admin-user

وظيفتها:
- تفعيل أو تعطيل Sub Admin
- تغيير المدينة الخاصة به
- تعديل اسمه
- لا تسمح بحذف أو تعطيل آخر Super Admin
- لا تسمح لـ Sub Admin باستخدامها
